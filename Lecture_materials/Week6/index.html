설치 전후

검사 도구의 설치

uv는 프로젝트의 Python 환경과 패키지 설치·실행을 관리한다. uv와 Python이 설치되어 있고, pyproject.toml이 있는 프로젝트 폴더에서 실행하는 예다.

설치할 도구를 기록

다른 버전의 검사 도구는 같은 코드를 다르게 판정할 수 있다. 다음 명령의 --dev는 검사 도구를 개발용 의존성으로 기록한다.
uv add --dev pytest mypy black flake8 flake8-bugbear pre-commit

무엇을 자동화하나

전: 각자 설치 명령과 버전을 기억한다. 후: pyproject.toml에 개발 의존성이 기록되고 uv.lock에 해결된 버전이 고정된다. uv run은 실행 전에 프로젝트 환경을 동기화한다.

예제로 보는 장점

  • 같은 버전으로 시작: 팀원이 같은 pyproject.toml과 uv.lock을 받으면, uv run black --version으로 기록된 Black 버전을 확인할 수 있다. 설치할 버전을 따로 전달할 필요가 줄어든다.
  • 업데이트 범위 선택: Black만 갱신하려면 uv lock --upgrade-package black을 실행한다. 전체 도구를 한꺼번에 올리지 않고, lock 파일의 변경과 포맷 결과를 검토한다. 호환성 때문에 관련 의존성도 바뀔 수 있다.

검사 대상의 차이

pytest에서 코드 품질 검사로

인사 함수의 요구사항은 문자열 이름을 받아 "Hello, 이름!"을 반환하는 것이다. pytest는 작성된 입력·기대값 사례를 실행하는 테스트 도구다.

테스트가 확인하는 사례

greet(name: str) -> str가 Hello, {name}!를 반환한다. uv run pytest -q는 greet("Hee")의 결과를 확인한다.

테스트 밖의 문제

greet(42)는 실행 결과가 그럴듯해도 타입 약속 위반이다. 작은따옴표 표기는 동작하지만 팀 표기가 달라진다. 사용하지 않는 import os는 불필요하다. mypy는 타입 위반, Black은 표기, flake8은 미사용 import를 각각 판정한다.

검사 명령의 실행

프로젝트 루트에는 pyproject.toml·uv.lock과 도구 설치 기록이 있다. src는 패키지 코드, tests는 테스트 폴더, example.py는 패키지 사용 예다.

입력과 반환값

mypy

타입 힌트는 함수가 받을 값과 돌려줄 값의 종류를 코드에 적는 표기다. 아래는 example.py의 전체 예이며, mypy는 코드를 실행하지 않고 그 약속을 검사한다.

처리 전

def greet(name: str) -> str:
    return f"Hello, {name}!"

print(greet(42))  # Hello, 42!
실행은 성공한다. 타입 힌트는 실행 중 인수를 차단하지 않는다.

처리 후

name: str은 문자열 입력, -> str은 문자열 반환 약속이다. mypy가 호출을 분석하면 정수 인수가 약속과 다름을 보고한다. 문자열 "42"로 고친다.
uv run mypy example.py를 실행하면 int 대신 str이 필요하다는 오류가 나온다.

예제로 보는 장점

  • 목록의 원소도 검사: names: list[str] = ["Hee", 42]는 “문자열 목록” 약속을 어긴다. mypy가 42를 지적하고, "42"로 바꾸면 이 오류가 사라진다.
  • 함수 사용법 확인: greet(name: str) -> str만 읽어도 문자열을 넣고 문자열을 받는다고 알 수 있다. greet("Hee").upper()처럼 문자열 기능을 쓸 수 있지만, 정확한 인사 문구는 설명·테스트로 확인한다.

두 도구의 보완 관계

mypy 와 pytest 의 차이

greet는 문자열 이름을 받아 "Hello, 이름!"을 반환해야 한다. 아래처럼 "Goodbye"를 반환하도록 잘못 고친 경우를 비교한다.

처리 전

def greet(name: str) -> str:
    return "Goodbye"
반환 타입은 str이므로 mypy는 통과한다. 그러나 greet("Hee")는 요구 결과와 다르다.

처리 후

uv run pytest -q는 Hello, Hee! 기대값과 실제 Goodbye를 비교해 실패한다. 반환문을 return f"Hello, {name}!"로 고치면 이 테스트도 통과한다. 타입과 기능을 각각 자동 검사한다.

예제로 보는 장점

  • 여러 입력을 다시 확인: 인사 함수의 테스트에 "" → "Hello, !", "희" → "Hello, 희!"를 추가한다. 함수를 바꾼 뒤 pytest를 한 번 실행하면 두 사례의 결과를 다시 확인한다.
  • 테스트 파일의 간섭 방지: pytest의 tmp_path는 테스트마다 별도 임시 폴더를 준다. A가 그 안에 result.txt를 만들어도 B의 폴더에는 없다. 파일 준비를 돕는 fixture를 쓰면 이전 테스트의 파일을 잘못 읽는 일을 줄인다.

불필요한 코드 검출

flake8의 코드 규칙

flake8은 코드 규칙 위반을 보고하는 린터다. src/hello_open_source/greeting.py에 아래 코드가 있고, 다른 파일에는 규칙 위반이 없다고 가정한다.

처리 전

import os


def greet(name: str) -> str:
    return f"Hello, {name}!"
os는 쓰지 않는다. pytest와 mypy는 이 문제를 판정하지 않는다.

처리 후

uv run flake8 src tests example.py
# F401: os imported but unused
첫 줄을 지우면 진단 없이 종료 코드 0이다. flake8은 진단을 자동화하며 기본 실행은 파일을 고치지 않는다.

예제로 보는 장점

  • 실행 전 이름 오타 발견: name = "Hee" 다음에 print(nmae)를 쓰면 F821이 정의되지 않은 이름을 보고한다. 프로그램을 실행해 그 줄에 도달하기 전에 오타를 찾는다.
  • 긴 분기 함수의 검토 대상 선정: 서로 독립된 if가 3개인 함수는 복잡도 4다. flake8 --max-complexity 3으로 검사하면 C901이 나온다. 기본 실행에는 없는 기준이며, 경고는 버그 확정이 아니라 함수를 나눌지 검토할 단서다.

공유 기본값 검출

bugbear의 추가 규칙

flake8-bugbear: flake8에 추가하는 오류·설계 실수 검사 규칙이다. 이름을 목록에 넣는 remember 함수에서, 이전 호출의 이름이 남는 공유 기본값 문제를 살펴본다.

처리 전 · 이전 호출의 값이 남음

def remember(name, names=[]):
    names.append(name)
    return names

remember("Hee") → ["Hee"]
remember("Kim") → ["Hee", "Kim"]

원인: 기본값 []는 함수 정의 때 한 번 생성된다. 두 호출이 같은 목록을 받고, append가 원본 목록에 이름을 추가해 이전 값이 남는다.

처리 후 · 호출마다 새 목록 생성

def remember(name, names=None):
    if names is None:
        names = []
    names.append(name)
    return names

remember("Hee") → ["Hee"]
remember("Kim") → ["Kim"]

B006은 공유 기본값 경고다. 수정 후에는 names를 생략한 호출마다 새 목록이 만들어진다.

충돌 없는 설정

포매터와 린터의 기준

Black은 표기를 고치고 flake8은 규칙 위반을 알린다. 두 도구의 버전과 설정을 공유해 같은 코드를 서로 모순된 기준으로 판정하는 일을 줄인다.

두 파일의 줄 길이 설정

프로젝트 루트에서 각각 설정한다.

# pyproject.toml
[tool.black]
line-length = 88
# .flake8
[flake8]
max-line-length = 88

83자 코드 줄의 판정

Black이 포맷을 유지한 83자 줄을 가정한다. flake8 기본 제한 79자에서는 길이 경고 E501이 난다. 두 설정을 88자로 맞추면 이 줄의 길이 경고가 사라진다.

Black은 나눌 수 없는 긴 문자열을 88자보다 길게 남길 수도 있다. 같은 길이 설정이 모든 코드의 통과를 보장하지는 않는다.

한 프로젝트의 판정

전체 품질 검사

프로젝트 루트에서 실행한다. src는 패키지 코드, tests는 테스트, example.py는 사용 예이며 uv에 네 도구가 개발 의존성으로 기록되어 있다.

실행 순서

uv run pytest -q
uv run mypy src tests example.py
uv run black --check src tests example.py
uv run flake8 src tests example.py
각 명령은 프로젝트에 기록된 도구로 실행된다. Black의 --check는 파일을 고치지 않고 수정 필요 시 종료 코드 1, 불필요하면 0을 반환한다.

판정

모두 종료 코드 0이면 예제의 테스트·타입·표기·규칙 검사에 통과했다. 실패 시 해당 도구의 진단을 보고 수정한 뒤 다시 실행한다. 요구사항 누락은 코드 리뷰로 확인한다.

수동 검사에서 커밋 전 자동 실행으로

pre-commit의 개념과 자동 실행

pre-commit은 git commit 직전에 등록한 명령을 실행하는 도구다. hook은 이처럼 특정 시점에 실행할 작업이며, stage는 git add로 커밋할 내용을 골라 둔 공간이다.

도입 전 · 네 명령을 직접 실행

uv run pytest -q
uv run mypy src tests example.py
uv run black src tests example.py
uv run flake8 src tests example.py

개발자가 검사 명령을 잊으면 greet(42) 같은 타입 오류가 있어도 Git 자체는 커밋을 허용한다.

도입 후 · 커밋 시 네 도구 실행

네 명령을 .pre-commit-config.yaml에 등록하고 로컬 Git hook을 설치한다.

git add .
git commit -m "Update greeting"

pytest → mypy → Black → flake8 순서로 실행한다. greet(42)를 mypy가 보고하면 커밋은 중단된다. Black이 파일을 고쳐도 확인·재등록 후 다시 커밋한다.

예제 프로젝트: src는 코드, tests는 테스트, example.py는 사용 예다. 명령을 한 번 등록하면 매 커밋 때 네 명령을 직접 입력할 필요가 없다.

작업 파일과 stage 확인

pre-commit의 사용과 커밋 재시도

네 도구의 Git hook을 설치한 저장소다. stage는 git add로 커밋할 내용을 골라 둔 공간이다. src/hello_open_source/greeting.py의 x=1만 표기 수정이 필요하고 다른 검사는 통과한다고 가정한다.

첫 검사와 커밋

git add .
git commit -m "Update greeting"

네 도구의 설치·설정이 끝난 상태에서 커밋하면 자동 검사가 실행된다. 이 예제에서 mypy·Black·flake8은 src·tests·example.py를 검사하고, pytest는 테스트를 실행한다.

pytest ........ Passed
mypy .......... Passed
Black ......... Failed
flake8 ........ Passed

출력 요약: Black이 x=1을 x = 1로 수정한 실행은 실패로 표시된다. 커밋 중이었다면 커밋이 만들어지지 않는다.

수정 확인 후 다시 커밋

git diff -- src/hello_open_source/greeting.py
git add src/hello_open_source/greeting.py
git commit -m "Update greeting"

git diff로 작업 파일과 stage의 차이를 확인한다. git add가 수정본을 stage에 넣는다. pre-commit은 자동으로 stage하지 않는다.

pytest ........ Passed
mypy .......... Passed
Black ......... Passed
flake8 ........ Passed

모두 통과하면 커밋이 생성된다. 커밋 없이 먼저 검사하려면 uv run pre-commit run --all-files를 실행한다. 오류가 있으면 고치고 다시 stage·커밋한다.

도구별 전후 변화

Summary

문자열 이름을 인사 문자열로 바꾸는 greet 함수가 대상이다. 각 도구는 서로 다른 오류를 검사하므로 하나가 통과했다고 나머지가 통과한 것은 아니다.

검사와 수정

pytest: "Hello, Hee!"를 기대했는데 "Goodbye"면 실패한다.
mypy: 문자열 인수를 받는 greet(42)를 보고한다.
Black: x=1을 x = 1로 고친다.
flake8·bugbear: 미사용 import os와 공유 기본값 names=[]를 경고한다.

자동 실행

uv는 프로젝트의 도구를 설치·실행한다. pre-commit에 pytest·mypy·Black·flake8을 등록하면 커밋 전에 네 도구가 자동 실행된다. 실패·자동 수정 시 내용을 고쳐 다시 stage하고 커밋한다.
