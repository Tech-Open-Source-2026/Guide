AI와 오픈소스 책임

AI 사용

  • AI가 만든 코드는 실행·테스트·라이선스 확인을 거친 뒤 자신의 판단으로 제출한다.
  • 이해하지 못한 코드는 결과가 동작해도 설명 가능한 제출물이 아니다.

공개 협업

  • 외부 프로젝트에 Issue나 Pull Request를 보낼 때 재현 조건·수정 이유·영향 범위를 적는다.
  • 비밀정보와 불필요한 로그를 제거하고 프로젝트의 기여 규칙과 사람을 존중한다.
  • 실패한 시도도 원인과 수정 과정을 남기면 유효한 학습 근거가 된다.

11 · TWO-COLUMN-COMPARE

문제와 현재 해법 — 왜 Git을 사용하는가?

중심 문제와 현재 해법

  • 중심 문제는 여러 번 바뀌는 코드의 이전 상태와 변경 이유를 잃지 않고 병렬 변경을 통합하는 것이다.
  • 현재 해법은 Git이 각 개발자의 컴퓨터에 전체 이력을 저장하고 스냅샷·브랜치·병합으로 변경을 관리하는 것이다.

효과와 연결 질문

  • Git은 네트워크 없이도 변경을 기록하고 다시 연결된 뒤 공통 조상에서 서로의 작업을 합치게 한다.
  • 그렇다면 왜 코드 변경을 관리할 때 파일 복사나 하나의 공유 폴더보다 Git을 사용하는가?

13 · SUMMARY

Summary

강의 진행

  • 전반부는 패키지·의존성·테스트·CI, 후반부는 문서·릴리스·커뮤니티·최신 도구로 진행한다.
  • 한 학기 동안 개인 저장소를 공개 프로젝트 수준의 실행·검증·문서 구조로 개선한다.
  • 시험·실습·Discussion은 개념 판단과 실제 저장소 증거를 함께 평가한다.

왜 Git인가

  • Git은 프로젝트 파일의 한 시점 상태를 스냅샷으로 기록하고 앞 스냅샷과 연결한다.
  • 각 개발자는 전체 이력을 가진 채 독립된 브랜치에서 작업하고 공통 조상에서 변경을 합친다.
  • 네트워크가 없어도 변경을 기록하고 다시 연결된 뒤 다른 사람의 작업과 통합할 수 있다.
