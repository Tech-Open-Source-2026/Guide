docstring과 __doc__

필요성: 문서 도구가 함수 설명을 코드에서 직접 읽으려면 설명이 주석이 아니라 코드 객체에 저장되어 있어야 함 → docstring: 모듈 파일·함수 본문의 첫 문장 자리에 둔 문자열. Python이 docstring을 그 모듈·함수 객체의 __doc__ 속성에 저장.

src/hello_open_source/greeting.py · 전체

"""Greeting messages for the hello-greet command."""


def greet(name: str) -> str:
    """Return a greeting for ``name``.

    :param name: Name to greet.
    :returns: Text in the form ``Hello, <name>!``.
    """
    return f"Hello, {name}!"

첫 줄: 모듈 docstring · 함수 안 세 따옴표 문자열: 함수 docstring. :param name:·:returns:: 인수와 반환값을 적는 reStructuredText 필드 목록.

루트에서 실행 · repr: 줄바꿈을 \n으로 보여 주는 출력

uv run python -c "from hello_open_source import greeting; print(repr(greeting.__doc__)); print(repr(greeting.greet.__doc__))"
'Greeting messages for the hello-greet command.'
'Return a greeting for ``name``.\n\n:param name: Name to greet.\n:returns: Text in the form ``Hello, <name>!``.\n'

# 주석과 비교 · 아래 4줄을 파일로 저장해 uv run python으로 실행 · 출력 None: 주석은 __doc__에 저장되지 않음

def hello():
    # Say hello.
    return "hi"
print(hello.__doc__)
None

apidoc 확장으로 참조 원본 생성

필요성: Sphinx는 .rst만 읽고 코드의 docstring은 읽지 않음 → 확장 없이는 함수 설명을 .rst에 복사(코드를 고치면 문서가 낡음)하거나, 모듈마다 docstring을 불러오는 .rst를 손으로 쓰고 새 모듈마다 추가해야 함. apidoc 확장(확장: Sphinx에 기능을 더하는 Python 모듈): 빌드할 때마다 패키지의 모듈 목록을 읽어 이 .rst와 참조 입구 modules.rst를 자동 생성.

docs/conf.py · extensions = [] 줄을 아래로 교체

extensions = ['sphinx.ext.apidoc']
apidoc_modules = [
    {
        'path': '../src/hello_open_source',
        'destination': 'reference',
    },
]
extensions켤 확장의 모듈 이름 목록
apidoc_modules문서화할 패키지 목록. 딕셔너리({키: 값}) 하나가 패키지 하나
'path'conf.py가 있는 docs/ 기준 패키지 위치
'destination'docs/ 기준 생성 위치 → docs/reference/

생성된 docs/reference/hello_open_source.rst 일부 · \_는 밑줄 그대로

hello\_open\_source.greeting module
-----------------------------------

.. automodule:: hello_open_source.greeting
   :members:
   :undoc-members:
automodule모듈을 import해 docstring과 시그니처(함수 이름·인수·반환 타입)를 가져옴
:members:밑줄로 시작하지 않는 이름을 실음
:undoc-members:docstring이 없는 이름도 실음

autodoc이 만든 API 참조 페이지

필요성: apidoc이 만든 .rst에는 automodule 지시문만 있어 함수 설명 화면은 아직 없음 → autodoc 확장: automodule이 가리키는 모듈을 import해 함수 시그니처와 docstring을 HTML로 변환. 아래 화면: docs/_build/reference/hello_open_source.html의 greeting 모듈 부분.

greeting.py의 코드화면의 위치
모듈 docstring모듈 제목 아래 첫 문장
def greet(name: str) -> str시그니처 greet(name: str) → str. 타입 힌트를 그대로 표시
함수 docstring 첫 문단시그니처 아래 설명
:param name: · :returns:Parameters · Returns 표

코드의 docstring을 고치면 다음 빌드(-E)에서 API 참조 페이지도 따라 바뀜. 설명을 .rst에 복사해 두면 함수를 고칠 때 docstring과 .rst 두 곳을 함께 고쳐야 함.

필요성: 로컬에서 빌드한 HTML은 내 컴퓨터에만 있어 독자가 볼 수 없음 → Read the Docs: GitHub 저장소에 커밋된 파일로 Sphinx 빌드를 실행하고 결과 HTML을 공개 주소에 올리는 서비스. 기본 브랜치에 push할 때마다 다시 빌드·공개.

hello-open-source/.readthedocs.yaml · 전체

version: 2
build:
  os: ubuntu-24.04
  tools:
    python: "3.12"
sphinx:
  configuration: docs/conf.py
  fail_on_warning: true
python:
  install:
    - method: uv
      command: sync

빌드 환경과 명령: 저장소 루트의 .readthedocs.yaml이 결정. .readthedocs.yaml이 없으면 빌드 실패.

Read the Docs 프로젝트와 등록 절차

필요성: Read the Docs는 어느 저장소의 어느 브랜치를 빌드해 어떤 주소에 공개할지 알아야 함 → 프로젝트: GitHub 저장소 하나를 Read the Docs에 연결한 문서 빌드·공개 단위. 프로젝트마다 이름(Name), 저장소 주소, 기본 브랜치, 빌드 기록, 공개 주소를 가짐.

등록 절차 (.readthedocs.yaml을 커밋·push한 뒤)

① readthedocs.org에 GitHub 계정으로 로그인: Read the Docs가 내 저장소 목록을 읽도록 허용

② 대시보드 → Add project → 저장소 이름 검색·선택 → Continue

③ 저장소 정보로 미리 채워진 Name·Default branch 확인 → Next

④ 설정 파일 안내 화면에서 This file exists: 저장소 루트에 .readthedocs.yaml이 이미 있다는 확인

⑤ 등록 직후 Default branch의 첫 빌드 자동 시작

등록 항목뜻과 예제 값
Name공개 주소의 앞부분. 예: hello-open-source → https://hello-open-source.readthedocs.io/en/latest/. 다른 사람이 쓰는 이름은 사용 불가
Repository빌드할 GitHub 저장소. 예: https://github.com/<본인ID>/hello-open-source
Default branch주소의 latest가 가리킬 브랜치(보통 main). 이 브랜치에 push할 때마다 다시 빌드

등록 뒤 결과: 성공한 빌드만 공개 주소에 반영. 빌드 결과와 기록은 다음 장의 프로젝트 페이지에서 확인.
