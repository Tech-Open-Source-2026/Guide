명령 입력에서 출력까지

src/hello_open_source/cli.py 전체 코드

  • CLI는 Command-Line Interface, 즉 터미널의 명령 입력 접점이다. sys.argv의 0번은 명령 이름, 1번부터 사용자 입력이다.
  • import sys는 인수 목록을, from ... import greet는 인사 함수를 가져온다. 이름이 없으면 world를 선택한다.
  • print는 문자열 뒤에 줄바꿈을 출력한다. return 0은 정상 종료 값이며 -> int는 정수 반환 표기다.
import sys
from hello_open_source.greeting import greet


def main() -> int:
    if len(sys.argv) > 1:
        name = sys.argv[1]
    else:
        name = "world"
    print(greet(name))
    return 0

첫 pytest 테스트

tests/test_greeting.py: 준비 → 실행 → 단언

  • pytest는 테스트를 찾아 실행·보고하는 도구다. 한 테스트는 입력·기대값·비교를 묶고, 스위트는 여러 테스트의 집합이다.
  • from ... import greet는 공개 함수를 가져온다. "Hee"를 준비해 호출하고 결과를 actual에 담는다.
  • assert는 비교가 참이면 통과, 거짓이면 실패다. test_는 발견 규칙, -> None은 반환값이 없다는 형식 표기다.
from hello_open_source.greeting import greet


def test_greet_with_name() -> None:
    actual = greet("Hee")
    assert actual == "Hello, Hee!"

실패 진단과 회귀 검사

기대값이 계약과 다른 경우

  • 계약과 실제값은 Hello, Hee!인데 기대값을 Hi, Hee!로 쓴 상황이다. 테스트를 고친다.
  • E는 오류 설명, -는 오른쪽 기대값, +는 왼쪽 실제값이다.
assert greet("Hee") == "Hi, Hee!"
E  AssertionError
E    - Hi, Hee!
E    + Hello, Hee!
1 failed

구현이 계약과 다른 경우

  • 회귀는 변경 때문에 이전 동작이 깨지는 현상이다. 구현에서 !를 지웠다면 구현을 고친다.
  • 정확한 기대값의 테스트를 유지한다. 같은 결함이 재등장하면 같은 입력으로 다시 실패한다.
계약: "Hello, Hee!"

구현에서 ! 삭제 → "Hello, Hee"
기존 테스트 실행 → 1 failed

구현의 ! 복구 → "Hello, Hee!"
같은 테스트 실행 → 1 passed

fixture로 테스트마다 새 목록 준비

tests/test_state.py를 이 코드로 교체

  • fixture는 테스트에 필요한 값을 준비하는 함수다. 전역 목록 대신 매번 새 목록을 반환한다.
import pytest

@pytest.fixture
def fruits():
    return ["apple"]

def test_append(fruits):
    fruits.append("banana")
    assert fruits == ["apple", "banana"]

def test_len(fruits):
    assert len(fruits) == 1

등록 → 요청 → 값 전달

  • import pytest로 도구를 가져오고 @pytest.fixture로 바로 아래 준비 함수를 등록한다.
  • 테스트 인자 fruits와 같은 이름의 함수를 pytest가 실행한다. 반환한 목록이 그 인자로 전달된다.
  • 기본 설정은 테스트마다 준비한다. 이 함수 안의 ["apple"]이 새 목록이므로 앞 테스트의 추가 내용이 남지 않는다.
python -m pytest tests/test_state.py -q
test_append: ["apple"] → ["apple", "banana"]
test_len:    새 ["apple"] → 길이 1
2 passed

순서를 반대로 지정해도 2 passed

parametrize로 입력 두 개 검사

tests/test_greeting.py를 이 코드로 교체

  • 동일한 인사 검사를 복사하지 않고 입력·기대값의 두 행으로 표현한다. greet의 구현은 처음과 같다.
import pytest
from hello_open_source.greeting import greet

@pytest.mark.parametrize("name, expected", [
    ("Hee", "Hello, Hee!"),
    ("Kim", "Hello, Kim!"),
])
def test_greet(name, expected):
    assert greet(name) == expected

한 데이터 행마다 테스트 한 번

  • @pytest.mark.parametrize는 아래 테스트를 데이터 행마다 실행한다. "name, expected"는 값을 받을 두 인자의 이름이다.
  • 첫 행은 name="Hee", expected="Hello, Hee!"다. 둘째 행은 Kim의 인사말을 비교한다.
  • fixture는 준비할 값을 제공하고, parametrize는 검사할 입력 사례를 늘린다. 이 예제는 fixture 없이 실행한다.
python -m pytest tests/test_greeting.py -q
Hee → "Hello, Hee!"와 비교: 통과
Kim → "Hello, Kim!"와 비교: 통과
2 passed

공백 입력의 기대값과 coverage의 한계

교재 Figure 5.2: 입력에 따른 경로

  • 파란 Code는 코드, 초록 점선은 정상 경로, 자홍 점선은 경계·오류 경로다. 화살표는 실행 방향이다.
  • Edge case는 경계 사례, Error handling은 오류 처리다. 예제에서 빈 이름은 허용한 정상 입력이다.

coverage_demo/에서 파일의 세 테스트를 모두 실행한다. -v는 테스트별 이름과 결과를 표시한다.

test_greeting.py의 누적된 세 테스트

기존 두 검사를 유지한다. test_space는 “공백 한 칸도 기본 인사말을 반환한다”는 새 요구를 검사한다.

from greeting import greet
def test_name():  # 11장에서 작성
    assert greet("Hee") == "Hello, Hee!"
def test_empty():  # 12장에서 추가
    assert greet("") == "Hello, world!"
def test_space():  # 이 장에서 추가
    assert greet(" ") == "Hello, world!"
test_greeting.py::test_name  PASSED
test_greeting.py::test_empty PASSED
test_greeting.py::test_space FAILED
1 failed, 2 passed / 줄 coverage 100%

Hee·빈 문자열은 기대값과 같아 통과한다. 공백은 실제 "Hello, !"와 기대 "Hello, world!"가 달라 실패한다. 100%는 이 요구의 충족을 보장하지 않는다.

Summary

실행 결과에서 판단할 수 있는 것

  • -e .로 설치한 기존 Python 소스를 고치면 새 실행에서 변경을 읽는다. pytest는 이름 규칙으로 테스트를 찾아 단언의 참·거짓을 보고한다.
  • fixture가 테스트마다 새 목록을 준비하면 순서에 따른 간섭을 막는다. parametrize는 입력·기대값 두 행을 두 사례로 실행한다.
  • coverage 75%는 미실행 3번 줄을 가리켰다. 빈 이름 테스트를 더해 100%가 되어도 공백 입력의 정확성은 별도 단언으로 확인해야 한다.
