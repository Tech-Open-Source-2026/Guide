## 목표와 완성 산출물

기존 `hello-open-source` 패키지의 인사 함수를 여러 입력으로 검사하고, 입력 목록을 사용하는 테스트끼리 서로 영향을 주지 않게 만든다. 함수 반환값 검사와 테스트별 새 상태 준비를 하나의 테스트 스위트로 완성한다.

학생이 작성하는 Python 소스는 `test_greeting_suite.py` 한 개이며, 빈 줄·주석을 포함하여 100줄 이내다. 강의에서 사용한 패키지 구현은 검사 대상이다. 평가하는 신규 소스는 테스트 파일 한 개다. 검사 대상 패키지의 소스와 pyproject.toml도 같은 제출 commit에 보존하여 교수자가 실제 함수 구현을 확인할 수 있게 한다.

## 입력과 실행 환경

- Python 3.10 이상과 기존 `hello-open-source` 프로젝트의 가상환경을 사용한다. 모든 명령은 프로젝트 루트에서 실행한다.
- 검사 대상은 강의 2장의 `src/hello_open_source/greeting.py`다. `greet(name)`은 `f"Hello, {name}!"`를 반환한다. 별도 `coverage_demo/`의 빈 이름 처리 버전과 구분한다.
- 제공 파일은 이 안내를 담은 `README.md`뿐이다. 입력이 짧으므로 아래 표를 사용하며 시작 코드나 정답 `.py` 파일은 제공하지 않는다.

| 입력 | 기대 반환값 |
|---|---|
| `"Hee"` | `"Hello, Hee!"` |
| `"Kim"` | `"Hello, Kim!"` |

## 수행 과정

1. 프로젝트 루트에 `test_greeting_suite.py`를 만들고 공개 함수 `greet`를 가져온다. 표의 두 행을 `pytest.mark.parametrize`로 전달해 정확한 인사말과 비교한다. 테스트 함수 하나가 사례 두 개를 검사하게 한다.
2. 기본 설정의 fixture로 테스트마다 새 이름 목록 `["Hee"]`를 만든다. 이 fixture를 요청하는 테스트 두 개를 작성한다. 하나는 목록에 `"Kim"`을 추가한 뒤 두 이름의 인사말을 기대값과 비교한다. 다른 하나는 목록이 여전히 `["Hee"]`인지 확인한다. 목록을 전역 변수로 공유하지 않는다.
3. 아래 명령으로 사례 네 개가 모두 통과하는지 확인하고, 인사 함수의 줄 coverage를 측정한다. 실패하면 기대값과 구현의 계약을 대조해 원인을 고친다.
4. 완성한 테스트 파일과 실제 실행 기록을 제출한다. AI로 초안을 작성할 수 있지만 실제 결과는 직접 확인한다.

## 실행과 확인

```bash
python -m pip install -e .
python -m pip install pytest pytest-cov
python -m pytest test_greeting_suite.py -q \
  --cov=hello_open_source.greeting --cov-report=term-missing
```

`-e .`는 현재 프로젝트 소스를 읽도록 설치한다. 기존 Python 함수 본문을 저장한 뒤 새로 실행하면 재설치 없이 변경을 읽는다. 첫 두 명령은 현재 Python 환경을 변경한다.

마지막 명령은 지정한 테스트 파일만 실행한다. `-q`는 간결한 보고, `--cov=hello_open_source.greeting`은 인사 모듈만 측정, `term-missing`은 미실행 줄 번호 표시다. 소스는 바꾸지 않고 `.coverage`에 측정값을 기록하며 기본 재실행은 이전 값을 교체한다.

강의 2장과 같은 구현의 핵심 결과는 다음과 같다. 경로 표시와 경과 시간은 환경에 따라 달라질 수 있다.

```text
4 passed
src/hello_open_source/greeting.py: Stmts 2 / Miss 0 / Cover 100%
```

테스트 함수는 세 개지만 매개변수화한 함수가 두 사례로 실행되므로 총 네 개다. 100%는 인사 모듈의 두 실행 가능 줄을 모두 실행했다는 뜻이다. 결과의 정확성은 단언이 검사하며 모든 가능한 이름의 정확성을 증명하지는 않는다.
