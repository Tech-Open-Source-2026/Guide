# 직접 의존성 선언 누락 확인

## 목표

프로젝트에서 직접 사용하는 외부 패키지 목록과 직접 의존성으로 선언한 목록을 비교해, 선언에서 빠진 패키지를 찾는다. 강의에서 배운 “직접 사용하는 외부 패키지는 직접 의존성으로 선언한다”는 원칙을 코드로 확인한다.

## 제공 파일과 환경

- `README.md`: 실습 안내문.
- `dependencies.json`: 세 프로젝트의 사용 패키지와 선언 패키지 목록.
- Python 표준 라이브러리의 `json`으로 파일을 읽는다. 추가 패키지 설치는 필요 없다. JSON은 목록과 이름 붙은 값을 저장한 데이터 형식이다.

각 프로젝트의 `project`는 이름, `used`는 직접 사용하는 외부 배포 패키지 이름 목록, `declared`는 직접 의존성으로 선언한 배포 패키지 이름 목록이다. 이름은 소문자이고 버전 조건은 없으며, 제공 데이터에서는 이름을 그대로 비교한다. 표준 라이브러리는 이 목록에 넣지 않는다.

이 데이터는 코드와 의존성 선언에서 목록을 추려 놓은 예제다. 실제 소스나 `pyproject.toml`을 자동 분석하거나 패키지 설치 여부·버전 호환성을 검사하는 실습은 아니다. `used`에는 설치된 모든 패키지가 아니라 직접 사용하는 패키지만 들어 있다.

## 처리 순서

1. `dependencies.json`을 UTF-8로 읽는다.
2. 각 프로젝트에서 `used`에는 있지만 `declared`에는 없는 패키지를 찾는다.
3. 같은 누락 패키지는 한 번만, 이름 오름차순으로 출력한다.
4. 프로젝트는 입력 순서로 처리한다. 누락이 없으면 `없음`을 출력한다. 선언했지만 사용 목록에 없는 패키지는 누락으로 세지 않는다.

## 기대 결과

```text
greeting: termcolor
report: 없음
chart: matplotlib, pandas
```

`greeting`은 사용하는 `termcolor`의 선언이 빠져 있다. `report`는 직접 사용하는 패키지를 모두 선언했으므로 누락이 없다. 선언에만 있는 `termcolor`는 누락이 아니다. `chart`는 직접 사용하는 두 패키지를 선언하지 않았다.

## 작성과 실행

AI와 함께 `main.py`를 작성한다. 주석과 빈 줄을 포함해 100줄 이내의 Python 파일 하나로 완성한다. 제공된 데이터를 코드 안에 옮겨 적거나 기대 출력만 직접 출력하지 말고, 파일을 읽어 결과를 계산한다.

학생 저장소의 `Week04/`에 제공 데이터를 복사하고 같은 폴더에 `main.py`를 작성한다. 터미널에서 `Week04/`로 이동한 뒤 아래 명령을 실행한다.

```bash
python main.py
```

이 명령은 입력 파일을 읽고 결과를 터미널에 출력한다. 입력 파일은 수정하지 않는다. 편집기 실행 버튼을 쓰는 경우에도 작업 폴더를 `Week04/`로 맞춘다. 환경에서 Python 명령이 `python3`이면 같은 명령 이름을 사용한다.

## 제출과 개인 이해 확인

`Week04/main.py`와 제공된 입력 데이터 파일을 함께 commit하고 push한다. Python 소스는 한 개만 제출한다. 별도의 고찰 보고서·실행 결과 파일·AI 대화 기록은 제출하지 않는다.

실습 완료 후 현장에서 자신의 코드와 데이터·처리·결과의 이해를 묻는 비공개 서술형 문항 한 개에 답한다.

## 평가기준

3. 세 프로젝트의 결과를 입력 순서로 출력하고, 누락 없음·중복 제거·이름 정렬 규칙과 기대 결과를 만족하는가?
